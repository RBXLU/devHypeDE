# Rust с нуля — по коду HypeDE

Этот текст не заменяет учебник. Он делает другое: проводит по **этому** проекту
от самых простых файлов к самым сложным и объясняет, зачем в каждом месте
написано именно так. Читать лучше с открытым редактором.

Если параллельно захочется систематики — [«Язык программирования Rust»](https://doc.rust-lang.ru/book/)
переведён на русский и бесплатен.

## Почему вообще Rust

Композитор — программа, которая не имеет права падать: вместе с ней исчезает
весь рабочий стол вместе с несохранёнными документами. При этом он работает с
памятью на низком уровне, с буферами кадров и с чужими процессами.

Rust устроен так, что целый класс ошибок (обращение к освобождённой памяти,
гонки между потоками) не проходит компиляцию. Компилятор придирчив, зато
упавший композитор — редкость, а не норма.

Побочный эффект: **компилятор будет много ругаться**. Это не признак того, что
вы плохо пишете. Это и есть работа: не «написать и запустить», а
«договориться с компилятором».

## 1. Функции, `enum` и `match`

Откройте `crates/hype-anim/src/easing.rs`.

```rust
pub enum Easing {
    Linear,
    EaseInQuad,
    EaseOutCubic,
    CubicBezier(CubicBezier),
}
```

`enum` в Rust — это не список чисел, как в C. Это «одно из»: значение
`Easing` — либо `Linear`, либо `EaseOutCubic`, либо `CubicBezier` **вместе с
данными внутри**. Такой тип называют суммой, и на нём держится половина кода
в проекте.

Разбирают его через `match`:

```rust
match self {
    Easing::Linear => t,
    Easing::EaseOutCubic => 1.0 - (1.0 - t).powi(3),
    Easing::CubicBezier(bezier) => bezier.apply(t),
}
```

Компилятор проверяет, что перечислены **все** варианты. Добавите в `Easing`
новую кривую — код перестанет собираться во всех местах, где её забыли
обработать. Это не придирка, а самая полезная особенность языка: забыть
ветку невозможно.

Обратите внимание на отсутствие `return` в конце функций. Последнее выражение
без точки с запятой и есть результат.

### Тесты живут рядом с кодом

В конце файла:

```rust
#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn linear_is_identity() {
        for i in 0..=10 {
            let t = i as f64 / 10.0;
            assert_close(Easing::Linear.apply(t), t);
        }
    }
}
```

`#[cfg(test)]` означает «собирать только при `cargo test`»: в готовую программу
тесты не попадут. `use super::*` втягивает всё из внешнего модуля.

Запустите:

```bash
cargo test -p hype-anim
```

## 2. Трейты и обобщённые типы

`crates/hype-anim/src/lerp.rs`.

```rust
pub trait Lerp: Copy {
    fn lerp(self, other: Self, t: f64) -> Self;
    fn distance(self, other: Self) -> f64;
}
```

Трейт — это «что тип умеет». Похоже на интерфейс, но реализовать трейт можно
для любого типа, включая чужой.

```rust
impl Lerp for f64 {
    fn lerp(self, other: Self, t: f64) -> Self {
        self + (other - self) * t
    }
    // ...
}
```

Теперь любой код, которому нужно «смешивать значения», пишется один раз для
всех типов сразу:

```rust
pub struct Animation<T: Lerp> { /* … */ }
```

`<T: Lerp>` читается как «для любого типа `T`, который умеет `Lerp`». Одна и та
же `Animation` двигает и число, и прямоугольник окна. При этом, в отличие от
динамических языков, всё проверяется при компиляции и не стоит ни такта во
время работы.

## 3. `Option` и `Result`: ошибки как значения

`crates/hype-config/src/shortcut.rs`.

В Rust нет `null` и нет исключений. Вместо них два типа:

* `Option<T>` — «значение либо есть (`Some(x)`), либо нет (`None`)»;
* `Result<T, E>` — «получилось (`Ok(x)`) либо не получилось (`Err(e)`)».

```rust
pub fn from_str(s: &str) -> Result<Self, ShortcutParseError> {
    let trimmed = s.trim();
    if trimmed.is_empty() {
        return Err(ShortcutParseError::Empty);
    }
    // ...
}
```

Вызывающий **обязан** что-то сделать с результатом — просто проигнорировать его
компилятор не даст. Отсюда правило, которому следует весь проект: ошибка
конфига должна быть видна, а не превращаться в молча неработающую привязку.

Удобные сокращения, которые встретятся везде:

```rust
let x = foo()?;                     // при ошибке — выйти и вернуть её наверх
let Some(value) = maybe else {      // «если нет — выходим»
    return;
};
value.unwrap_or_default()           // взять или значение по умолчанию
```

`unwrap()` — «я уверен, что здесь всё хорошо, иначе паника». В коде среды он
встречается только там, где иначе быть не может, и всегда с объяснением:

```rust
.expect("привязка по умолчанию должна разбираться")
```

## 4. Итераторы и замыкания

`crates/hypede-compositor/src/layout.rs`, функция `focus_target`.

```rust
candidates
    .iter()
    .filter_map(|(id, rect)| {
        let center = rect.center();
        // ...
        Some((*id, along + across * 2.0))
    })
    .min_by(|a, b| a.1.total_cmp(&b.1))
    .map(|(id, _)| id)
```

Читается сверху вниз как цепочка: перебрать кандидатов → отбросить неподходящие
и посчитать оценку для остальных → выбрать наименьшую → взять из пары
идентификатор.

`|(id, rect)| { … }` — замыкание, безымянная функция. Вертикальные палочки —
её аргументы.

Важно: цепочка **ничего не делает**, пока в конце не вызвано что-то
завершающее (`min_by`, `collect`, `sum`). Промежуточные шаги не создают
временных массивов — всё сворачивается в один проход.

Ещё одно место, которое стоит прочесть целиком — `arrange`: там видно, как из
области экрана и списка окон получаются прямоугольники, и почему зазоры
ужимаются, если экрана не хватает.

## 5. Владение: главная идея языка

`crates/hypede-compositor/src/workspace.rs`.

У каждого значения ровно один владелец. Когда владелец заканчивается, значение
освобождается. Никакого сборщика мусора и никакого ручного `free`.

Ссылки бывают двух видов:

```rust
pub fn active(&self) -> &Workspace          // читаю, не меняю
fn active_mut(&mut self) -> &mut Workspace  // меняю
```

Правило: одновременно может существовать **либо** сколько угодно `&`, **либо**
ровно одна `&mut`. Именно поэтому в коде иногда встречается такое:

```rust
let path = {
    let mut state = state.borrow_mut();
    state.show_hidden = !state.show_hidden;
    state.history.current().to_path_buf()
};
refresh(&state, &widgets, &path);
```

Фигурные скобки здесь не для красоты: изменяемое заимствование должно
закончиться **до** вызова `refresh`, которому нужно своё. А `to_path_buf()`
делает копию пути, потому что отдавать наружу ссылку внутрь структуры,
которую сейчас отпустим, нельзя.

Когда компилятор ругается на заимствования, почти всегда помогает одно из двух:
сузить область видимости скобками или скопировать нужное значение.

## 6. `Rc<RefCell<…>>`: общее состояние в интерфейсе

`crates/hypede-files/src/ui.rs`.

У кнопок в GTK есть обработчики, и каждому нужен доступ к общему состоянию
окна. Одного владельца тут не выходит — владельцев много.

```rust
let state = Rc::new(RefCell::new(AppState { /* … */ }));

back.connect_clicked({
    let state = Rc::clone(&state);
    move |_| {
        let path = state.borrow_mut().history.back();
        // ...
    }
});
```

* `Rc` — счётчик ссылок: значение живёт, пока на него смотрит хоть кто-то.
* `RefCell` — перенос проверки заимствований со времени компиляции на время
  работы. `borrow()` — почитать, `borrow_mut()` — поменять.
* `Rc::clone` копирует не данные, а ссылку.
* `move` перед замыканием означает «забери используемое внутрь себя»; без него
  замыкание не пережило бы функцию, в которой создано.

Плата за гибкость: если случайно взять `borrow_mut()` дважды одновременно,
программа не откажется компилироваться, а упадёт во время работы. Поэтому
заимствования в этом коде всегда короткие — на одно-два действия.

## 7. Состояние целой программы

`crates/hypede-compositor/src/state.rs` — самый большой файл проекта, и его
полезно прочитать не ради деталей, а ради формы.

`HypeState` — одна структура, в которой лежит всё: состояние протоколов
Wayland, пространство окон, настройки, рабочие столы, анимации. Обработчики
событий получают `&mut HypeState` и меняют её.

Это скучно и предсказуемо, и в этом смысл: чтобы понять, что происходит,
достаточно посмотреть в одно место, а не искать состояние по десяти объектам.

Посмотрите `relayout()` — там видно всю цепочку: взять область экрана, спросить
у раскладки прямоугольники, сказать анимациям новые цели, отправить клиентам
размеры.

## 8. Потоки и каналы

`crates/hype-ipc/src/transport.rs` и `crates/hypede-compositor/src/ipc.rs`.

Чтение из сокета блокирующее, а останавливать композитор нельзя. Поэтому
соединения обслуживаются отдельными потоками, а запросы передаются в главный
цикл по каналу:

```rust
let (reply_tx, reply_rx) = mpsc::channel();
requests.send(PendingRequest { request, reply: reply_tx })?;
let response = reply_rx.recv()?;
```

Здесь снова вылезает главная идея языка. Чтобы отдать данные в другой поток,
их нужно **передать** — компилятор не позволит двум потокам одновременно
менять одно и то же. Гонка данных в Rust не «редкая ошибка», а то, что просто
не соберётся.

Общий список подписчиков защищён замком:

```rust
subscribers: Arc<Mutex<Vec<Subscriber>>>
```

`Arc` — тот же `Rc`, но пригодный для нескольких потоков; `Mutex` — замок.

## Три упражнения

Каждое — настоящее улучшение среды, не выдуманное задание.

### Упражнение 1: своя кривая анимации

**Файл:** `crates/hype-anim/src/easing.rs`

Добавьте в `Easing` вариант `EaseOutQuint` (формула: `1 - (1 - t)^5`).
Компилятор сам покажет `match`, который нужно дополнить. Впишите новую кривую
в тест `every_curve_starts_at_zero_and_ends_at_one` и запустите
`cargo test -p hype-anim`.

Потом поставьте её в `AnimationConfig::default` для `window_close` и посмотрите
на разницу.

### Упражнение 2: колонка даты в файловом менеджере

**Файлы:** `crates/hypede-files/src/fs.rs`, `crates/hypede-files/src/ui.rs`

В `Entry` уже есть поле `modified`. Сделайте функцию, которая превращает его в
подпись вроде «сегодня, 14:32» или «17 сен». Напишите на неё тест (время
подавайте параметром, а не берите системное, — иначе тест будет проходить не
каждый день). Затем добавьте в `build_row` ещё одну `Label`.

### Упражнение 3: индикатор громкости на панели

**Файлы:** `crates/hypede-shell/src/status.rs`, `crates/hypede-shell/src/panel.rs`

По образцу `read_battery` сделайте чтение громкости. Проще всего вызвать
`wpctl get-volume @DEFAULT_AUDIO_SINK@` и разобрать вывод — разбор вынесите в
отдельную функцию и покройте тестом на нескольких строках вывода, включая
случай с выключенным звуком.

## Как читать ругань компилятора

Ошибки в Rust длинные, но устроены одинаково:

```
error[E0502]: cannot borrow `self.windows` as mutable because it is also
              borrowed as immutable
  --> src/state.rs:312:9
   |
310|         let visible = self.workspaces.visible_windows();
   |                       ---------------- immutable borrow occurs here
312|         self.windows.remove(&id);
   |         ^^^^^^^^^^^^^^^^^^^ mutable borrow occurs here
```

Порядок чтения: сначала стрелка `-->` (где), потом две подчёркнутые строки
(что с чем конфликтует), и только потом текст. В девяти случаях из десяти
лечится копией (`.to_vec()`, `.clone()`) или скобками, сужающими область
заимствования.

Полезные команды:

```bash
cargo check                # быстрая проверка без сборки
cargo clippy               # советы по стилю, часто дельные
rustc --explain E0502      # подробный разбор конкретной ошибки
```
