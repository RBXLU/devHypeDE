# Как попасть в pacman

Короткий ответ: **в сам официальный репозиторий CachyOS или Arch попасть
нельзя** — туда пакеты добавляют только сопровождающие дистрибутива, и только
после того, как проект станет известным и стабильным. Зато есть три рабочих
пути, и первые два доступны прямо сейчас.

## 1. Собрать пакет у себя (работает сразу)

```bash
git clone https://github.com/RBXLU/devHypeDE
cd devHypeDE
makepkg -si
```

`makepkg` соберёт HypeDE и установит его как обычный пакет pacman: он попадёт
в базу, его увидит `pacman -Q`, и удалить его можно через `pacman -R`.

Проверить, что пакет собран правильно:

```bash
makepkg --printsrcinfo > .SRCINFO   # понадобится для AUR
namcap PKGBUILD                      # придирки к самому PKGBUILD
namcap hypede-git-*.pkg.tar.zst      # придирки к готовому пакету
```

`namcap` ставится из репозитория: `sudo pacman -S namcap`.

## 2. Выложить в AUR (обычный путь для нового проекта)

AUR — это пользовательский репозиторий Arch. Туда принимают любой рабочий
пакет, и оттуда его поставит любой пользователь Arch и CachyOS через `yay`,
`paru` и любой другой помощник.

### Подготовка

1. Зарегистрируйтесь на [aur.archlinux.org](https://aur.archlinux.org/).
2. Добавьте свой SSH-ключ в профиле AUR (Account → SSH Public Key).
3. Проверьте, что имя пакета свободно: поиск по `hypede`.

### Публикация

```bash
# Клонируем пустой репозиторий будущего пакета
git clone ssh://aur@aur.archlinux.org/hypede-git.git
cd hypede-git

# Кладём туда PKGBUILD из проекта
cp ~/devHypeDE/packaging/PKGBUILD .

# .SRCINFO обязателен: AUR читает метаданные именно из него
makepkg --printsrcinfo > .SRCINFO

git add PKGBUILD .SRCINFO
git commit -m "HypeDE 0.1.0"
git push
```

Всё: пакет появится в AUR через несколько секунд, и ставиться будет так:

```bash
yay -S hypede-git
```

### Что важно для AUR

* Имя с суффиксом `-git` означает сборку из ветки. Для сборки из выпуска имя
  будет просто `hypede`, а в `PKGBUILD` появятся `source=(...)` с архивом
  версии и `sha256sums`.
* В `.SRCINFO` нельзя вносить правки руками — он всегда генерируется.
* При каждом обновлении `PKGBUILD` заново генерируйте `.SRCINFO` и делайте
  коммит: AUR отклонит push без этого.
* В репозитории AUR должны лежать только `PKGBUILD`, `.SRCINFO` и мелкие
  вспомогательные файлы. Исходники остаются на GitHub.

## 3. Свой репозиторий pacman (если нужны готовые сборки)

AUR отдаёт рецепт, а не собранный пакет: у каждого пользователя HypeDE будет
компилироваться минут десять. Свой репозиторий отдаёт уже собранное.

### Собрать репозиторий

```bash
mkdir -p ~/repo/x86_64
cp hypede-git-*.pkg.tar.zst ~/repo/x86_64/
cd ~/repo/x86_64
repo-add hypede.db.tar.gz *.pkg.tar.zst
```

Получатся `hypede.db.tar.gz` и `hypede.files.tar.gz` — это и есть база
репозитория.

### Выложить

Подойдёт что угодно, отдающее файлы по HTTP: GitHub Pages, GitHub Releases,
любой веб-сервер, объектное хранилище.

### Подключить у пользователя

В `/etc/pacman.conf`:

```ini
[hypede]
SigLevel = Optional TrustAll
Server = https://rbxlu.github.io/hypede-repo/$arch
```

Затем:

```bash
sudo pacman -Sy hypede
```

### Подпись пакетов

`SigLevel = Optional TrustAll` означает «ставить без проверки подписи». Для
своей машины это приемлемо, для чужих — нет. Правильный вариант:

```bash
# Создать ключ для подписи пакетов
gpg --full-generate-key

# Подписать пакеты
gpg --detach-sign --use-agent hypede-git-*.pkg.tar.zst

# Собрать базу с подписями
repo-add -s -v hypede.db.tar.gz *.pkg.tar.zst
```

Пользователь один раз импортирует и подписывает ваш ключ:

```bash
sudo pacman-key --recv-keys ВАШ_ОТПЕЧАТОК
sudo pacman-key --lsign-key ВАШ_ОТПЕЧАТОК
```

и меняет `SigLevel` на `Required DatabaseOptional`.

## 4. Попасть в репозиторий CachyOS

Это уже вопрос не техники, а доверия. CachyOS собирает свои пакеты в
[репозитории на GitHub](https://github.com/CachyOS/CachyOS-PKGBUILDS), и
предложение пакета выглядит как обычный pull request. Прежде чем его подавать,
имеет смысл довести проект до состояния, в котором:

* есть выпуски с версиями, а не только ветка;
* среда запускается на настоящем железе, а не только вложенным окном;
* пакет проходит `namcap` без замечаний;
* есть люди, которые им пользуются, — обычно это AUR с голосами.

Иначе говоря: сначала AUR, потом собственный репозиторий, потом — разговор с
сопровождающими.

## Проверка перед публикацией

```bash
# Собирается ли из чистого дерева
git clean -xdf && makepkg -f

# Нет ли лишних зависимостей и не забыты ли нужные
namcap hypede-git-*.pkg.tar.zst

# Что именно попадёт в систему
tar -tf hypede-git-*.pkg.tar.zst | head -40
```
