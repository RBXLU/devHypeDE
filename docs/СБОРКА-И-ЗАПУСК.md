# Сборка и запуск

## Зависимости

### CachyOS и Arch

```bash
sudo pacman -S --needed rust cargo pkgconf \
  wayland libxkbcommon libinput libdrm mesa seatd \
  gtk4 pango cairo gdk-pixbuf2 glib2

# Не обязательно, но по умолчанию среда рассчитывает на них:
sudo pacman -S --needed foot inter-font ttf-jetbrains-mono
```

### Debian и Ubuntu

```bash
sudo apt install build-essential pkg-config \
  libwayland-dev libxkbcommon-dev libxkbcommon-x11-0 libinput-dev libudev-dev \
  libgbm-dev libdrm-dev libseat-dev libegl1-mesa-dev libgles2-mesa-dev \
  libgtk-4-dev
```

Rust ставится через [rustup](https://rustup.rs/); нужна версия не ниже 1.80.

## Сборка

```bash
git clone https://github.com/RBXLU/devHypeDE
cd devHypeDE
cargo build --release
```

Собираются пять программ в `target/release`:

| Программа | Что делает |
|---|---|
| `hypede-comp` | композитор — сама среда |
| `hype-shell` | панель; с `--launcher` — поиск приложений |
| `hype-files` | файловый менеджер |
| `hype-settings` | параметры |
| `hypectl` | управление из терминала |

## Запуск вложенным окном

Самый удобный способ пробовать: HypeDE открывается обычным окном внутри
текущего сеанса, и если что-то сломается, рабочий стол не пострадает.

```bash
./target/release/hypede-comp
```

В журнале появится имя сокета Wayland (обычно `wayland-1`). Программы внутри
среды запускаются горячими клавишами, а снаружи — так:

```bash
WAYLAND_DISPLAY=wayland-1 foot
```

Работает и из другого сеанса Wayland, и из X11.

## Установка пакетом

```bash
cd devHypeDE
makepkg -si
```

После установки HypeDE появится в списке сеансов дисплейного менеджера — SDDM,
GDM, greetd, любого, читающего `/usr/share/wayland-sessions`.

> **Важно.** Полноценный вход в сеанс требует бэкенда DRM/KMS, а он пока не
> реализован (см. [дорожную карту](ДОРОЖНАЯ-КАРТА.md)). В версии 0.1 среда
> рассчитана на запуск вложенным окном. Файл сеанса уже подготовлен, чтобы
> пакет не пришлось переделывать.

## Настройки

```bash
# Записать файл со значениями по умолчанию и посмотреть, что там есть
hype-settings          # и нажать «Применить»

# Или вручную
$EDITOR ~/.config/hypede/config.toml
```

Перечитать настройки в работающем сеансе: `Super+Shift+R` или

```bash
hypectl dispatch reload
```

## Управление из терминала

```bash
hypectl ping                      # композитор жив?
hypectl windows                   # список окон
hypectl dispatch workspace 3      # перейти на третий рабочий стол
hypectl dispatch spawn foot -e htop
hypectl subscribe window focus    # поток событий, по строке JSON на событие
```

Последнее удобно в скриптах:

```bash
hypectl subscribe workspace | while read -r line; do
  echo "$line" | jq -r '.index'
done
```

## Разработка

```bash
cargo test --workspace          # 291 тест, ни одного медленного
cargo clippy --workspace        # придирки компилятора
cargo fmt --all                 # единое форматирование

# Подробный журнал композитора
RUST_LOG=debug ./target/debug/hypede-comp
```

Логику раскладки, анимаций и цвета можно отлаживать вообще без запуска среды —
она покрыта тестами и не зависит ни от Wayland, ни от GTK:

```bash
cargo test -p hypede-compositor layout
cargo test -p hype-anim
cargo test -p hype-theme palette
```

## Если что-то не работает

**`не удалось открыть окно композитора`** — нет доступного дисплея. Нужен
работающий сеанс Wayland или X11; в чистой консоли вложенный режим не
запустится.

**`Library libxkbcommon-x11.so could not be loaded`** — при запуске поверх X11
нужен пакет `libxkbcommon-x11` (Arch) или `libxkbcommon-x11-0` (Debian).

**`по адресу ... уже работает композитор`** — сеанс HypeDE уже запущен. Это
защита: второй запуск не отберёт управление у первого.

**Приложения выглядят чужеродно** — значит, не прочитан `~/.cache/hypede/theme.css`.
Его пишет композитор при старте и при каждой смене темы; проверьте, что файл
существует.
